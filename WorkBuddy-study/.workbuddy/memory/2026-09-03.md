## Kong 与腾讯云 TKE Ingress 选型调研（知识梳理）

**交付物**：`D:\files\WorkBuddy-study\Kong与TKE-Ingress选型手册.html`（单文件手册，含 14 节：TKE 四条 Ingress 路线、Kong 对象模型、版本兼容矩阵、云原生网关 Kong × TKE 对接、发布回滚方案、配置片段、排查清单）

**核心事实（已核来源，后续复用可直接引用）**：

1. **TKE Ingress 四条路线**：
   - 应用型 CLB（`ingress.class: qcloud`，缺省即它）— 一条 Ingress = 一个 CLB 实例 = 一个 IP，**IP 不收敛**；VPC-CNI 可直连 Pod
   - Nginx Ingress — CLB + 集群内 nginx，IP 收敛；三种方案官方推荐 `Deployment + LB 直连 Pod`（需 VPC-CNI）
   - 云产品托管 — 专享型 API 网关 / 云原生网关（Kong）
   - Others — 自建 Ingress Controller + 自定 IngressClass，TKE 不提供 SLA

2. **重大变更（必须记住）**：上游 `ingress-nginx` 2025-11 宣布退役，best-effort 维护至 **2026-03**，之后归档无安全补丁。TKE 的 `NginxIngress` 扩展组件**已停止版本更新和维护**（需自建或走应用市场）。阿里云 ACK 同类组件 2026-11-30 停止维护。→ 用户若在用 Nginx Ingress，迁移已不是"要不要"而是"排期"问题。

3. **KIC 版本现状**：
   - 3.5.x（2025-07-04 发布，EOL 2027-12-18）支持 Gateway API 1.3
   - 3.4.x（LTS，EOL 2027-12-18）支持 Gateway API 1.2，K8s 1.29–1.32 官方推荐
   - **2.12.x EOL 2026-09-25（本月到期）**
   - K8s 1.27–1.35 均在支持范围；Kong Gateway 3.4.x–3.12.x 与 KIC 3.x 全系兼容
   - KIC 3.0 起 **Helm 是唯一官方安装方式**；**Helm 不升级 CRD**，每次升级必须单独 `kubectl kustomize .../crd?ref=v3.4 | kubectl apply -f -`
   - 安全公告 GO-2026-5010：Secret-backed plugin 配置经非敏感 diagnostics 端点泄漏（v3.4.15 受影响）

4. **腾讯云云原生网关（TSE/TSF）基于开源 Kong，兼容 Kong 3.x**，对接 TKE 两种方式：
   - 服务来源关联（控制台：实例 → 服务路由 → 服务来源 → 新建，类型选"容器服务"，需同 VPC）
   - 开启托管 KIC（TSF 控制台 → 云原生网关 → 实例详情 → Ingress → 关联容器集群，可同 VPC / CCN / 对等连接；IngressClass 默认 `kong`）
   - **三个硬约束**（需工单核实）：① 仅对微服务场景（作为 Polaris 北极星服务接入层）支持白名单新购，其余场景不支持新接入；② 托管 KIC 文档列出版本仅 2.7.0 / 2.5.0 / 1.3.4，远落后开源 3.5.x；③ 仅 Ingress 2.7.0 支持关联多个容器集群

5. **Kong 对象模型**：Route → Service → Upstream → Target，+ Consumer（凭证主体）、Plugin（可挂全局/Service/Route/Consumer）。K8s Service 在 Kong 里被拆成 Service（不变）+ Upstream/Target（可调优）。

6. **迁移工具**：`ingress2gateway` 1.0（SIG Network，2026-03 发布），支持 30+ ingress-nginx annotation，带控制器级集成测试。用法 `ingress2gateway print --namespace my-api --providers=ingress-nginx > gwapi.yaml`。**是迁移助手不是一键替换**，`configuration-snippet` 类不可翻译。

**待用户核实**：云原生网关开通资格、托管 KIC 实际内核版本、集群网络模式（VPC-CNI / Global Router）。

## 追问：0.2 节四个问题怎么自查（不靠问人）

**用户问**：清单 0.2 节那四个问题（中间件是否共用 / 怎么隔离 / 跨集群怎么打通 / 有没有跨地域），我能自己查吗？

**结论**：问题 1、2、3 **完全能自查，且比问人准**（配置是事实，人的记忆会错）；问题 4 一半能查（延迟实测），一半必须有控制台权限。**唯一查不出来必须问的**：历史事故、云托管实例规格/连接数上限、CEN 带宽包水位、责任边界。

**方法论（可复用）**：不看架构图，看**业务 Pod 实际拿到的配置**。三环境跑同一套代码、注入不同配置 → 把连接串拉出来横向一比，隔离模型自动浮现。
判定顺序：`host` 是否同一 IP/域名 → 是则共用同一实例 → 再查四个隔离字段（jdbc 库名 / `redis://host:6379/N` 的 N / MQ topic 前缀 / Nacos namespace）→ 任一字段三环境相同 = 该维度没隔离。

**重要技术判断**：Redis 用 db index 隔离、MySQL 同实例不同库，都只是**逻辑隔离**——`FLUSHALL`、内存打满、连接数打满、慢 SQL 打满 CPU 都是**实例级**的，照样互相影响。写文档或给人讲时要点破这点。

⚠️ **脚本已按用户要求删除**（用户：「别脚本了，还是我自己一点一点找吧」→ 用户偏好手敲命令逐步排查，不喜一次性脚本，已写入 MEMORY.md 交付形式偏好）。下述设计要点在**手工排查**时仍适用，不要再生成 .sh 文件。

原交付物（已删）：`D:\files\WorkBuddy-study\probe-mw.sh`
设计要点：
- 全程只读，不自动 exec 进业务容器（第 7 段只打印命令模板）
- **自动跳过密码/密钥字段**（`SKIP` 正则过滤 password/token/ak/sk 等），不打印 Secret 明文 —— 输出要存文件、可能外传，这条必须有
- Secret 解码优先用 jq 的 `@base64d`，无 jq 时降级 `base64 -d`
- 三环境各跑一份输出后 `diff`，不一致处就是要问的问题
- 跨地域延迟判据：同地域 <2ms / 同城跨地域 5-10ms / 远距离（广州↔上海）约 30ms

**使用提示**：Windows 写的 .sh 传到 Linux 需先 `sed -i 's/\r$//' probe-mw.sh`。

### ⚠️ 两个已踩过的坑（复用必看）

1. **Node 22 没有全局 `CloseEvent`** → `simple-cdp` 在收尾阶段抛 `ReferenceError: CloseEvent is not defined`。
   **这不是无害噪音**：小页面（<512KB）能正常落盘，大页面会被**静默截断在 524288 字节（512KiB）**——实测 cnb.cool 首页截断成 512KB，补上 polyfill 后是 2.3MB。
   经 `--experimental-websocket` 也拿不到该全局，必须 polyfill。
   修复：在 workspace 放了 `sf.js`（4 行 wrapper：注入 CloseEvent 类 → 动态 import CLI）。修复后**零报错**。

2. **CLI 参数形态**（2.0.83 与网上文档不一致）：
   - `output` 是**位置参数**，不是 `-o`（用 `-o` 会直接打印帮助并退出）
   - `--load-deferred-images` 默认已是 `true`（懒加载图片默认就抓）
   - 常用：`--browser-executable-path`、`--browser-load-max-time`（默认 60s，慢站要调大）、`--output-directory`、`--max-resource-size`（默认 10MB）
   - 用 `node -e` 注入 polyfill 会因 argv 偏移把第二个位置参数误判成 URL（报 `Unreachable URL`），所以**必须用 wrapper 文件**，不能内联 `-e`

**已验证命令**（在 workspace 目录下执行）：
```
node sf.js "<URL>" "D:/files/某目录/输出.html" --browser-executable-path="C:/Program Files/Google/Chrome/Application/chrome.exe" --browser-load-max-time=120000
```
验证结果（cnb.cool 首页，2.3MB）：30 个 `data:` 内联资源、**img 外链残留 0**、仅剩 2 个备案号超链接（非资源）。
