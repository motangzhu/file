# 公司云服务学习指南 — 安全 / 网络 / 数据 / 可观测篇

> 面向:技术运维工程师,已读《新入职运维上手指南-TKE与Kong》。本篇覆盖你列出的其余 9 个服务。
> 目标:3 周内把这些服务学到"该精通的精通、该熟悉的熟悉、该了解的了解",能独立看懂告警、完成日常配置、知道出问题找谁。
> 原则:运维视角,不深挖每个产品的全部功能,只讲"你负责 UAT/SIT 应用 + Kong 网关时,这些服务对你意味着什么、你要会什么"。

---

## 关于"CNB 云原生网关"

你写的"CNB 云原生网关",腾讯云官方产品里对应的是 **TSE 云原生网关(基于 Kong)**——就是你负责的 SAAS-UAT/SIT-Kong。这块已在上一篇《新入职运维上手指南-TKE与Kong》第五、八节详述(路由/Service/插件/限流/灰度/鉴权/SOP)。

> 如果公司内部把网关另有命名(比如某个自建组件叫 CNB),**向组长确认**:是不是就是 TSE 云原生网关?还是另有自建网关?本篇不再重复网关内容。

下面讲其余 9 个服务。

---

## 一、这些服务在整体架构里的位置

参见对话中的"公司云上全栈架构"图。一条请求的完整路径:

```
公网用户
  │
  ▼
WAF (Web应用防火墙)      ── 拦恶意请求
  │
  ▼
CFW (云防火墙)           ── VPC 级流量管控
  │
  ▼
CLB (负载均衡)           ── 公网入口,分发到网关
  │
  ▼
云原生网关 Kong ★        ── 路由/限流/灰度/鉴权(你的核心)
  │
  ▼
主机安全组               ── 实例级端口/网段放行
  │
  ▼
TKE 应用 Pod ★           ── UAT/SIT 业务容器(你的核心)
  │
  ▼
TDSQL-C MySQL            ── 业务数据库
```

横向支撑:
- **云堡垒机**:你登录服务器/节点的跳板,所有操作留痕审计;
- **NAT 网关**:应用 Pod 出公网(拉镜像、调外部 API)走这里;
- **CEN 云联网**:跨 VPC / 跨地域网络互联。

全局覆盖:
- **腾讯云可观测平台**:指标、日志、告警、链路追踪,覆盖以上所有资源。

**关键认知**:这 9 个服务里,只有 4 个你要"精通"(CLB/可观测平台/主机安全组 + 已学的网关),其余是"熟悉"或"了解"。别平均用力。

## 二、学习优先级(参见"学习优先级矩阵"图)

| 级别 | 服务 | 你要达到的程度 |
|------|------|---------------|
| **精通** | CLB 负载均衡、腾讯云可观测平台、主机安全组 | 日常高频,能独立操作、看懂告警、独立排障 |
| **熟悉** | WAF、CFW 云防火墙、NAT 网关、TDSQL-C MySQL | 经常接触,会看监控/告警、会做简单配置、出问题知道找谁 |

| **了解** | CEN 云联网 | 跨网互联,找网络组,知道链路走向即可 |

下面按这个分级展开。

## 三、精通级详解

### 3.1 CLB 负载均衡

**是什么**:腾讯云的四层/七层负载均衡,公网流量入口。你的 Kong 网关前面通常挂一个 CLB(把 uat.company.com 的公网请求分发到 Kong 实例)。

**控制台**:https://console.cloud.tencent.com/clb

**你要掌握到什么程度**:能看懂 CLB 配置(监听器、后端服务器、健康检查),能做简单调整(加后端、改权重),能排查"网关访问不通是不是 CLB 这层的问题"。

**关键概念**:
- **监听器(Listener)**:CLB 监听的端口和协议(如 80/443);
- **后端服务器/CVM**:CLB 把流量转发到哪(这里是 Kong 实例或 Kong 所在的 TKE Service);
- **健康检查**:CLB 定期探活后端,挂了自动摘除;
- **会话保持**:同一客户端粘到同一后端(部分场景需要);
- **证书**:HTTPS 监听器要挂 SSL 证书(也可能证书在 Kong 上,看架构)。

**日常操作(控制台)**:
| 操作 | 路径 |
|------|------|
| 看 CLB 列表 | CLB → 负载均衡 |
| 看监听器 | CLB 详情 → 监听器管理 |
| 看后端服务器 | 监听器 → 后端服务 |
| 看健康检查状态 | 后端服务 → 健康状态(是否"健康") |
| 看监控 | CLB 详情 → 监控(QPS、连接数、丢包) |
| 改后端权重 | 后端服务 → 修改权重(灰度常用) |

**与你职责的关系**:
- 网关访问不通?排查链路第一站就是 CLB:后端健康吗?监听端口对吗?安全组放行了吗?
- 域名解析到 CLB VIP,流量才进来——**确认 uat/sit 域名解析指向哪个 CLB VIP**(向组长要)。

**常见问题**:
| 现象 | 可能原因 |
|------|---------|
| 后端全部"异常" | Kong 没起/健康检查端口不对/安全组没放行 |
| 间歇 502 | 后端慢,健康检查超时 |
| 流量不均 | 权重没配,或会话保持粘死 |
| HTTPS 报证书错 | 证书过期/没挂对 |

**安全提示**:改 CLB 监听器/后端影响线上流量,**测试环境也要走变更流程**,改前截图留底,改后验证。

### 3.2 腾讯云可观测平台

**是什么**:原"云监控",现在升级为"腾讯云可观测平台(TCOP)",统一管指标、日志、告警、链路追踪。这是你的"眼睛",没有它你瞎巡检。

**控制台**:https://console.cloud.tencent.com/monitor

**你要掌握到什么程度**:能看懂各资源监控大盘、能配告警规则、能查日志(CLS)、能在故障时第一时间从监控定位异常时间点和受影响资源。

**四大块**:
1. **指标监控**:TKE(Pod CPU/内存)、CLB(QPS/延迟)、Kong(请求量/5xx)、TDSQL-C(连接数/慢查询)、CVM(节点资源)等;
2. **日志服务 CLS**:应用日志、Kong 访问日志、审计日志,支持检索;
3. **告警**:指标超阈值 → 告警(发群/短信/电话);
4. **链路追踪(若接入)**:APM,看一个请求经过哪些服务、各段耗时。

**日常操作(控制台)**:
| 操作 | 路径 |
|------|------|
| 看云监控大盘 | 云监控 → 监控大盘 |
| 看某资源指标 | 云监控 → 指标监控 → 选产品/资源 |
| 配告警 | 云监控 → 告警管理 → 告警策略 → 新建 |
| 看告警历史 | 云监控 → 告警管理 → 告警历史 |
| 查日志 | 日志服务 CLS → 日志集/主题 → 检索 |
| 配日志采集 | CLS → 采集配置(或 TKE 里配日志采集规则) |

**与你职责的关系**:
- **告警是命脉**。第一周必须确认:UAT/SIT 的告警发到哪个群?接收人有你吗?告警阈值谁定的?
- 日常巡检 = 看几个核心大盘:TKE Pod 状态、Kong QPS/5xx、CLB 连接数、节点资源;
- 故障来了第一动作:**看监控曲线**,定位"什么时候开始异常、哪些资源异常",比埋头看日志快。

**告警配置要点**:
- 别告警泛滥:阈值要合理(如 Pod CPU > 80% 持续 5 分钟才告,不是瞬时);
- 分级:P1(大面积不可用)电话/短信,P2/P3 群消息;
- 告警要可执行:告警内容带资源名、当前值、阈值、监控链接,别只一句"CPU高"。

### 3.3 主机安全组

**是什么**:腾讯云的"实例级防火墙",绑定在 CVM/CLB/Kong 实例上,控制进出流量(端口+网段)。注意:安全组是"白名单"逻辑——默认拒绝,放行了才通。

**控制台**:https://console.cloud.tencent.com/cvm/securitygroup (或 VPC → 安全组)

**你要掌握到什么程度**:能看懂某实例绑了哪些安全组、规则是什么;能加/改放行规则(如放行某端口给网关);能判断"访问不通是不是安全组挡的"。

**关键概念**:
- **入站规则**:外部 → 本实例(如放行 80/443 给 CLB);
- **出站规则**:本实例 → 外部(一般默认全放行,但有的安全组会限制);
- **规则优先级**:数字越小优先级越高,按顺序匹配;
- **来源/目标**:用网段(10.0.0.0/8)、安全组 ID、CLB ID 等表达。

**日常操作(控制台)**:
| 操作 | 路径 |
|------|------|
| 看安全组列表 | VPC → 安全 → 安全组(或 CVM→安全组) |
| 看规则 | 安全组详情 → 入站规则/出站规则 |
| 加规则 | 入站规则 → 添加规则(填端口、来源、策略:允许) |
| 绑定实例 | 安全组详情 → 关联实例 → 绑定 CVM/CLB |
| 看某实例绑了哪些 | CVM 详情 → 安全组 |

**与你职责的关系**:
- **80% 的"访问不通"是安全组问题**。Kong 打不到后端?后端 Pod 所在节点的安全组放行了 Kong 来源吗?堡垒机连不上节点?安全组放行了你的 IP 吗?
- 加端口要走变更(尤其生产),测试环境可稍宽松但也别全开 0.0.0.0/0。

**常见问题**:
| 现象 | 可能原因 |
|------|---------|
| A 访问 B 不通 | B 的入站规则没放行 A 的来源网段/端口 |
| 偶尔通偶尔不通 | 多安全组规则冲突,优先级问题 |
| 改了规则没生效 | 规则有缓存,等几秒;或绑错实例了 |

**安全红线**:
- 生产数据库端口(3306 等)**绝不**对公网 0.0.0.0/0 放行,只放内网来源;
- 测试环境也尽量收窄来源,别图省事全开。

## 四、熟悉级详解

### 4.1 WAF(Web 应用防火墙)

**是什么**:七层防护,挡 SQL 注入、XSS、CC 攻击、扫描器等。通常在 CLB 前面或集成在 CLB 上,是流量进入应用前的第一道安全关。

**控制台**:https://console.cloud.tencent.com/waf

**你要掌握到什么程度**:会看 WAF 告警和拦截日志、会加白名单(误拦截时放行)、知道 WAF 规则变更走安全组审批。

**关键概念**:
- **防护域名**:WAF 保护的域名(如 uat.company.com);
- **规则**:内置规则 + 自定义规则;
- **模式**:观察模式(只记不拦)/ 拦截模式(记且拦);
- **白名单**:正常请求被误拦时加白名单放行。

**日常操作**:
| 操作 | 路径 |
|------|------|
| 看拦截日志 | WAF → 攻击日志(按域名/时间/类型筛) |
| 看防护域名 | WAF → 防护配置 → 域名接入 |
| 加白名单 | WAF → 防护配置 → 白名单 |
| 看监控 | WAF → 监控大盘(请求量/拦截量) |

**与你职责的关系**:
- 测试反馈"接口 403/被拦"?先看 WAF 攻击日志是不是误拦,是的话加白名单(走安全组流程);
- 大量拦截告警?可能被刷或扫描,通知安全组。

**注意**:WAF 规则变更一般归**安全组**管,你别擅自关规则或加全局白名单,可能把防护拆了。

---

### 4.2 CFW(云防火墙)

**是什么**:VPC 级的云防火墙,分**南北向**(互联网↔VPC)和**东西向**(VPC 内子网间)流量管控。比安全组更上层、更集中。

**控制台**:https://console.cloud.tencent.com/cfw

**你要掌握到什么程度**:会看 CFW 拦截日志和访问控制规则、能判断"某流量是不是被 CFW 挡了"、规则变更找安全组。

**关键概念**:
- **访问控制规则**:允许/拒绝某网段到某网段的某端口;
- **入侵防御(IPS)**:内置威胁情报拦截;
- **流量日志**:所有经过 CFW 的流量记录。

**日常操作**:
| 操作 | 路径 |
|------|------|
| 看流量日志 | CFW → 日志审计 → 流量日志 |
| 看拦截日志 | CFW → 日志审计 → 入侵防御日志 |
| 看访问控制规则 | CFW → 访问控制 → 入站/出站/互联网边界 |
| 看监控 | CFW → 监控大盘 |

**与你职责的关系**:
- 排查"网关/应用访问外网不通"时,除了 NAT 和路由,记得查 CFW 有没有挡;
- CFW 规则变更归安全组,你提需求,他们改。

---

### 4.3 NAT 网关

**是什么**:VPC 内实例出公网的网关。你的 TKE Pod 要拉镜像、调外部 API、访问外网,都走 NAT。

**控制台**:https://console.cloud.tencent.com/vpc/nat

**你要掌握到什么程度**:知道 UAT/SIT VPC 用哪个 NAT、能看 NAT 监控(出网带宽/连接数)、能判断"应用出不去公网是不是 NAT 的问题"。

**关键概念**:
- **SNAT**:源地址转换(内网 IP → NAT 的公网 IP);
- **EIP**:NAT 绑的弹性公网 IP(出网用哪个 IP);
- **带宽**:NAT 出网带宽上限,超了会丢包。

**日常操作**:
| 操作 | 路径 |
|------|------|
| 看 NAT 列表 | VPC → NAT 网关 |
| 看监控 | NAT 详情 → 监控(出/入带宽、连接数) |
| 看 EIP | NAT 详情 → 弹性公网 IP |
| 看 SNAT 规则 | NAT 详情 → SNAT 规则(哪些子网走这个 NAT) |

**与你职责的关系**:
- Pod 拉镜像失败(ImagePullBackOff)?看是不是 NAT 出不去 / 带宽打满 / 目标仓库不通;
- 应用调外部 API 超时?查 NAT 连接数和带宽;
- 公司若有统一镜像仓库(内网),拉镜像不走 NAT,走内网。

### 4.4 TDSQL-C MySQL

**是什么**:腾讯云的云原生数据库(MySQL 兼容,原 CynosDB),存算分离,弹性扩缩。你的 UAT/SIT 应用连的就是它。

**控制台**:https://console.cloud.tencent.com/cynosdb

**你要掌握到什么程度**:**你不是 DBA,不深管数据库本身**。你要会的是:知道应用连哪个集群、账号密码在哪(Secret)、能看连接数/慢查询监控、出问题找 DBA。

**关键概念**:
- **集群**:一组数据库实例(主+只读);
- **接入地址**:VPC 内地址(读写分离地址/只读地址);
- **账号**:数据库账号密码(应用通过 Secret 拿到);
- **慢查询**:执行慢的 SQL,影响性能。

**日常操作**:
| 操作 | 路径 |
|------|------|
| 看集群列表 | TDSQL-C → 集群 |
| 看接入地址 | 集群详情 → 实例 → 接入地址(VPC) |
| 看账号 | 集群详情 → 账号管理 |
| 看监控 | 集群详情 → 监控(连接数/CPU/慢查询/QPS) |
| 看慢日志 | 集群详情 → 性能优化 → 慢日志 |

**与你职责的关系**:
- 应用报"数据库连接失败"?看:Secret 里的账号密码对不对?接入地址对不对?安全组放行了 3306 吗?集群状态正常吗?连接数打满了吗?
- 应用慢?看慢查询日志,把慢 SQL 截图发给开发/DBA,让他们优化;
- **别在数据库里直接改数据**,那是 DBA 的活,你只读排障。

**边界**:数据库结构变更、数据修复、备份恢复——**全部找 DBA**。

## 五、会用即可 + 了解

### 5.1 云堡垒机(会用即可)

**是什么**:运维登录服务器的统一跳板机,所有登录和操作都录屏审计。公司大概率规定:登 CVM/节点**必须走堡垒机**,不能直连 SSH。

**控制台**:https://console.cloud.tencent.com/bh

**你要掌握到什么程度**:会登录、会连目标主机、会传文件、知道操作会被录屏(别乱敲)。

**日常操作**:
- 登录堡垒机 Web → 选目标主机 → 双击建立 SSH/Web 终端会话;
- 文件传输:用堡垒机的文件传输功能(不是 scp);
- 你的所有操作**全程录屏**,出问题可回溯——所以**别在堡垒机里敲危险命令**(rm -rf 之类)。

**与你职责的关系**:
- 排查节点级问题(NotReady、磁盘满)需要 SSH 进节点 → 走堡垒机;
- 确认你有堡垒机账号、能连 UAT/SIT 集群的节点 CVM;
- 堡垒机的**用户/权限/审计规则归安全组管**,你只用,不改规则。

### 5.2 CEN 云联网(了解即可)

**是什么**:腾讯云的跨 VPC / 跨地域网络互联产品。把多个 VPC 加到同一个云联网里,它们就能互通。

**控制台**:https://console.cloud.tencent.com/vpc/ccn

**你要掌握到什么程度**:知道 UAT/SIT 的 VPC 是不是在云联网里、和哪些 VPC 互通、出跨网问题找网络组。

**与你职责的关系**:
- 如果 UAT 应用要连另一个 VPC 里的服务(如共用数据库/中间件),走云联网;
- 跨网访问不通?找网络组查云联网路由;
- 你不操作云联网,知道链路走向即可。

## 七、与你 UAT/SIT 职责的关系矩阵

| 服务 | 你日常用到的场景 | 出问题时你做什么 |
|------|----------------|-----------------|
| CLB | 网关前置入口、灰度改权重 | 看后端健康状态、监听器配置 |
| 可观测平台 | 每天巡检、告警响应 | 看监控曲线定位异常 |
| 主机安全组 | 加端口放行、排查不通 | 查入站规则、绑定的实例 |
| WAF | 测试报"被拦" | 看攻击日志、加白名单(走流程) |
| CFW | 跨网/出网不通排查 | 看流量日志、提需求给安全组 |
| NAT | Pod 拉镜像/调外部 API 不通 | 看带宽、连接数 |
| TDSQL-C | 应用连库失败、慢 | 看连接数/慢日志,找 DBA |
| 云堡垒机 | SSH 进节点排障 | 登录连主机(注意录屏) |
| CEN | 跨 VPC 访问不通 | 找网络组查路由 |

**记住一条排障主线**:
```
请求不通 / 慢
  ├─ 入口层:CLB 后端健康吗?监听对吗?
  ├─ 安全层:WAF 误拦?CFW 挡了?安全组放行了吗?
  ├─ 网关层:Kong 路由/插件/upstream 正常吗?(你的主场)
  ├─ 应用层:TKE Pod 状态?日志?
  ├─ 出网层:调外部 API?NAT 带宽/CFW?
  └─ 数据层:连库?TDSQL-C 连接数/慢查询?
```

## 写在最后

这 9 个服务听起来多,但对你来说真正要"精通"的只有 CLB、可观测平台、主机安全组三个(网关已在上一篇)。其余的:**知道在哪、会看、会找对人**,就够上岗了。

三个原则再强调:
1. **排障走链路**——从入口 CLB 一路追到数据库 TDSQL-C,别跳步;
2. **安全类变更走流程**——WAF/CFW/安全组规则别自己乱改,找安全组;
3. **数据库不碰数据**——TDSQL-C 你只看,改找 DBA。

把"向组长确认补充清单"和上一篇的 22 问合并,一次性问完,你的环境认知就齐了。
