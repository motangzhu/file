## TKE kubectl 连接排障（Windows）
- 环境：Windows，kubectl v1.36.3（WinGet 安装），config 在 `C:\Users\Administrator\.kube\config`。
- 现象：`kubectl config get-contexts` 返回空表，但 `config` 文件本身含正常 context（`cls-lqogop1w`）。
- 根因：`KUBECONFIG` 环境变量被设为指向不存在的 `cls-lqogop1w-config`，导致 kubectl 读错文件。
- 修复：PowerShell `[Environment]::SetEnvironmentVariable("KUBECONFIG", $null, "User")` 和 `"Machine"` 从注册表移除。注意：旧终端仍继承旧值，须**重开 Terminal** 才生效。
- 验证：`unset KUBECONFIG` 后 `get-contexts` 正常；`get nodes` 仍失败——因当前沙箱 DNS（`hdjt.hdad.local`）解析不了 `data.tke.cls-cloude.com`（Non-existent domain），属网络层问题，非配置问题。
- 待用户在能联网/已配 VPN 的终端实测；重点核对：config 中 server 是否为「公网 kubeconfig」的地址（生产公网+内网都开），并检查公网访问安全组是否放通本机 IP。
- 用户拓扑：生产集群公网+内网都开；测试集群只开内网（需 VPN / 跳板机 SSH 隧道 / TKE Cloud Shell）。
