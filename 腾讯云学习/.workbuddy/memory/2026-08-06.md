- 产出两张可视化图：CNB 产品架构图、CNB vs Jenkins 8维度对比图
- 核心知识点：
  - CNB = Cloud Native Build，基于 Docker 生态的声明式全链路开发者平台
  - 六大模块：代码托管、云原生构建、云原生开发、制品库、AI代码助手、任务集
  - 核心配置文件：.cnb.yml（声明式 YAML，Pipeline as Code，与代码同源）
  - 与 Jenkins 本质区别：声明式 vs 命令式、全托管 vs 自运维、一体化平台 vs 单一CI/CD引擎
  - 关键优势：百G缓存秒级准备、环境与资源解耦、弹性伸缩按量计费、原生AI集成
  - 版本：社区版（SaaS开箱即用）+ 企业版（部署至腾讯云VPC）

- **Q10** 建网关实例：TSE控制台→云原生网关→新建(选VPC/子网)→服务来源选Kubernetes(TKE)关联集群→建路由(域名/路径→后端Service+端口)；排障 kubectl get svc/endpoints
- **Q11** 插件：限流(令牌桶)、熔断、鉴权(key-auth/JWT/OAuth2)、灰度(canary权重/Header)、CORS、IP黑白名单、重写/重定向、可观测(监控/CLS/链路追踪)；控制台在路由/服务上绑定插件策略(全局/服务/路由级)
- **Q12** CLB 转发模式：四层(TCP/UDP/TCP SSL/QUIC, VIP+Port透传, 拿真实客户端IP) vs 七层(HTTP/HTTPS, 按域名/URL/Header, Cookie保持/SSL卸载)；四层适用数据库/游戏/音视频，七层适用Web/按域名路径分流
- **Q13** NAT网关：VPC↔公网地址转换；SNAT(多CVM共用公网IP出网) + DNAT(1对1映射入站)；vs CLB：NAT主出网(SNAT)、CLB主入站(一对多+健康探测)。功能互补
- **Q14** CLB+NAT组合：CVM不绑公网IP；入站走CLB绑内网CVM，出站默认路由0.0.0.0/0→NAT(SNAT)；安全收益=无公网IP无直连入口
- **Q15** 云联网CCN：VPC间/VPC-IDC内网互联，路由自学习/全网互联/链路选优；vs 对等连接：对等是两两互联需n*(n-1)/2条且手动配路由、已停跨地域；CCN一个实例加多VPC自动通、支持跨地域跨账号；网段不能重叠
- **Q16** 用CCN互通多VPC：云联网控制台→新建→关联多个VPC(可加专线/VPN网关)→路由自动学习→可选带宽包；验证 ping 对端内网IP；注意CIDR冲突、跨境需资质
- **Q17** 选型：CLB=入站流量分发(L4/L7)、云原生网关=应用层API治理(常位于CLB后)、NAT=出站出公网(非入口)；推荐链 外部→CLB→(云原生网关)→后端，后端出网→NAT
- CNB 制品库要点：地址 docker.cnb.cool；内置变量 ${CNB_DOCKER_REGISTRY}/${CNB_REPO_SLUG_LOWERCASE}/${CNB_COMMIT}；**流水线内推送免 docker login**，免 TCR 登录凭据
