## 排查：Claude Code "思考但不回答" 根因（续）
- 现象：发消息后无回答，实测代理偶发 500 `litellm.InternalServerError ... Connection error.. Model Group=ms-gdc6t9h5`。
- 根因：本机存在本地出口代理 **Clash Verge (127.0.0.1:7897)**（`HTTPS_PROXY/HTTP_PROXY` 环境变量指向它）。TI-ONE 域名不在 NO_PROXY 中，litellm→TI-ONE 必须走 7897，而 Clash Verge 当前无法转发该域名（返回 000）。直连（curl -x ""）TI-ONE 却是 200，证明链路本身通，只是被 7897 卡住。
- 修复：在 `~/.claude/litellm/start-proxy.sh` 与 `.bat` 中 `unset HTTP_PROXY HTTPS_PROXY` 并 `export NO_PROXY="...,.tencentcs.com"`，让 litellm 直连 TI-ONE，绕开 7897。重启代理后验证：/v1/messages 返回 `stop_reason:end_turn` 且含文本块，正常。
- 结论：Claude Code 配置本身没问题，是 Clash Verge 出口代理挡了 TI-ONE。只改了 litellm 启动脚本的 env，不影响系统其它走 Clash 的程序。
- 提醒：重启电脑后代理不会自启，需重开 start-proxy.bat；若 Clash Verge 哪天又能转发，可回退该绕过（但保留绕过更稳）。
