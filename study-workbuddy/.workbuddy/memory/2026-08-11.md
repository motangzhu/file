## 排障补充：用户执行 `curl ... | sh -` 没生成 kk
- 原因：下载静默失败（国内 GitHub Releases 被墙，`curl -sf` 失败无报错 → sh 收到空内容 → 不生成 kk）。
- 解决：手动下载 KubeKey **v3.1.9**（3.x 最新稳定版，支持 K8s 最高 v1.33）：`wget .../kubekey-v3.1.9-linux-amd64.tar.gz` 解压即 kk；GitHub 不通用 `mirror.ghproxy.com` 镜像；一键脚本务必带 `VERSION=v3.1.9`。
- 用户另要求给出 SSH 配置方式：方式A 密码(`password:`)、方式B 私钥免密(`ssh-keygen`+`ssh-copy-id` 含本机，配置用 `privateKey: /root/.ssh/id_rsa`)。已补进文档第3、4节。

## 用户执行 `kk create config --with-kubesphere` 报错 unknown flag → v4 关键行为变更
- **根因**：KubeKey **v4.0.x 把 `--with-kubesphere` 从 `kk create config` 移除了**（v3.x 才有），所以 `kk create config --with-kubernetes v1.34.3 --with-kubesphere v4.2.1` 报 `unknown flag: --with-kubesphere`。
- **但该 flag 在 `kk create cluster` 上仍有效**（v4.0.5 实测 `kk create cluster ... --with-kubesphere v4.2.3` 能装出 KS 并起 30880）。此外 `kk addons install -f ... --with-kubesphere v4.2.x` 可给已有集群追加 KS。
- **正确写法**：`kk create config --with-kubernetes v1.34.3`（仅 K8s，生成 config-sample.yaml，不带 KS flag）→ 编辑 hosts/NFS addon → `kk create cluster -f config-sample.yaml --with-kubesphere v4.2.1`。
- 文档已同步修正第4、5节；并补充两阶段兜底（先建 K8s 再 `kk addons install` 或 Helm ks-core）。
- 另：v4 的 `kk create config` 用 `-o`/默认输出（官方 v4 文档不含 `-f`，但 `kk create cluster -f` 仍有效）。
