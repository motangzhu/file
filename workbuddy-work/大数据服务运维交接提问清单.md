# 大数据服务运维交接提问清单

> 用途：组长把服务运维交给你，拿这份清单去问组长 / 前任，把答案记下来就是你的交接文档与后续 runbook 的素材。
> 适用背景：TKE（容器服务，测试 / 生产双集群）+ CNB（云原生构建 cnb.cool，负责构建 Docker 镜像）。

---

## 一、业务与职责范围（先搞清楚"我是谁"）
- 这个服务具体解决什么问题？属于 ETL / 实时计算 / 报表 / 特征服务 / 其他？
- 技术栈是什么？Spark / Flink / 自研 / 还是混合？有没有 Kafka、HDFS、ClickHouse、OLAP 等周边组件？
- 我的职责边界到哪一层？只管 K8s 上的部署运行，还是也要管数据质量 / 业务逻辑？
- 出问题时第一责任人是谁？我需要兜底到什么程度？有没有 on-call 要求？

## 二、架构与依赖（搞清楚"它连着谁"）
- 画一张数据流向图：数据从哪来（上游源）→ 怎么处理 → 落到哪（下游 / 落库）。
- 依赖哪些外部系统？Kafka topic、MySQL 库表、COS 桶、内部 API 的地址和权限？
- 哪些业务 / 报表 / 模型依赖这份输出？出问题的影响面有多大？
- 服务分几个模块 / 几个 Deployment？彼此怎么调用？

## 三、发版与变更流程（上次讲过的链路，现在要落到"我手上"）
- 代码仓库（CNB）地址？分支策略？打 Tag / Release 的规范？
- `.cnb.yml` 在哪？构建产物（镜像）的命名 / 打标签规则（有没有打版本号？还是用 latest？）？
- 测试集群、生产集群分别怎么部署？Helm / Kustomize / kubectl？配置怎么区分两套环境？
- 谁来审批发版？发布窗口是什么时候？能不能紧急发版？
- 回滚步骤是什么？（rollout undo / 切镜像标签 / Flink 从 Savepoint 恢复）有没有真正演练过？
- 最近一次发版是什么时候？顺不顺利？有没有遗留问题？

## 四、运行环境与 K8s（出事时你要能动手）
- TKE 测试 / 生产集群的 ID、地域、节点池构成（CPU / GPU / 竞价实例）、资源配额？
- 命名空间怎么划分？我的权限（RBAC）覆盖哪些资源、能不能动生产？
- 工作负载类型分布：Deployment / StatefulSet / Job(CronJob) / Operator 各有哪些？
- 存储怎么挂的？PVC / CFS / COS？有状态数据（如 HDFS、Checkpoint）持久化在哪？
- 网络怎么暴露？CLB / Ingress？Pod 之间访问规则？
- 配置和密钥（ConfigMap / Secret）放哪、怎么改？（强调：禁止登容器改文件）

## 五、监控、告警与值班（上线后天天看的东西）
- 监控看板在哪（云监控 / Prometheus / Grafana）？重点看哪些指标（作业成功率、数据延迟、Checkpoint、backpressure、资源水位）？
- 日志在哪查（CLS / ELK）？怎么按 Pod / 作业过滤？
- 告警发到哪（企业微信 / 电话）？告警分级？夜里谁接？
- 有没有值班表？升级（escalation）路径是什么（先找谁、再找谁）？

## 六、历史故障与坑（别人踩过的，你别再踩）
- 过去半年出过哪些典型故障？根因是什么？怎么恢复的？
- 最容易踩的坑（OOM、Checkpoint 失败、数据重复、依赖方变更、镜像 latest 导致环境不一致）？
- 有没有"千万别做"的操作清单（比如不能随便删 PVC、不能直连生产改配置、不能在高峰期发版）？

## 七、文档与联系人（找不到人时去哪查）
- 现有文档 / runbook 在哪？（Wiki、CNB README、腾讯云文档、内部知识库）
- 前任 / 领域专家是谁？出问题除了组长还能问谁？
- 相关的告警群、运维群、需求群分别是哪个？
